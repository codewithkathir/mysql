What is a database?


Before writing queries, learn the few words everyone uses.


Data is any fact: a name, a price, a date. A database is an organised place to store data so you can find it fast. Think of a school office with neat files instead of a messy pile of paper.


In MySQL, data lives in tables. A table looks like a spreadsheet:




WordMeaningSpreadsheet example


TableOne topic of data, like customersOne sheet


Column (field)One kind of information, like emailColumn heading


Row (record)One item, like one customerOne line


Primary keyA column that uniquely identifies each rowA roll number


Foreign keyA column that points to a row in another table“See sheet 2, row 5”




MySQL is a relational database management system (RDBMS). “Relational” means tables are connected through keys. SQL (Structured Query Language) is the language you use to talk to it. MySQL is free, popular, and used by sites like WordPress blogs and large web apps.


The five families of SQL commands




FamilyFull nameWhat it doesCommands


DDLData Definition LanguageBuilds and changes the structureCREATE, ALTER, DROP, TRUNCATE, RENAME


DMLData Manipulation LanguageAdds, changes and removes rowsINSERT, UPDATE, DELETE


DQLData Query LanguageReads dataSELECT


DCLData Control LanguageGives or removes permissionGRANT, REVOKE


TCLTransaction Control LanguageSaves or undoes a group of changesSTART TRANSACTION, COMMIT, ROLLBACK, SAVEPOINT

Your first commands


SELECT VERSION();          -- which MySQL version you have
SHOW DATABASES;            -- list all databases

Rules to rememberEvery statement ends with a semicolon ;. Keywords like SELECT are not case sensitive, but writing them in CAPITALS makes queries easier to read. Text values go inside single quotes: 'India'. Comments start with -- (dash dash space) or sit between /* */.








The sample database: shop_db


A tiny online shop with six tables. Every example on this site uses it.


erDiagram
  CATEGORIES ||--o{ PRODUCTS : contains
  CUSTOMERS ||--o{ ORDERS : places
  EMPLOYEES ||--o{ ORDERS : handles
  EMPLOYEES ||--o{ EMPLOYEES : manages
  ORDERS ||--|{ ORDER_ITEMS : has
  PRODUCTS ||--o{ ORDER_ITEMS : "sold in"



How to read it: one category has many products. One customer places many orders. One order has many order items, and each item is one product. Each employee may have a manager, who is also an employee.


Run this whole script once. If you ever break the data while practising, run it again to start fresh.


-- =========================================
--  shop_db : sample database for learning
-- =========================================
DROP DATABASE IF EXISTS shop_db;
CREATE DATABASE shop_db;
USE shop_db;

CREATE TABLE categories (
  category_id   INT AUTO_INCREMENT PRIMARY KEY,
  category_name VARCHAR(50) NOT NULL UNIQUE
);

CREATE TABLE products (
  product_id   INT AUTO_INCREMENT PRIMARY KEY,
  product_name VARCHAR(100) NOT NULL,
  category_id  INT,
  price        DECIMAL(10,2) NOT NULL CHECK (price >= 0),
  stock        INT NOT NULL DEFAULT 0,
  FOREIGN KEY (category_id) REFERENCES categories(category_id)
);

CREATE TABLE customers (
  customer_id INT AUTO_INCREMENT PRIMARY KEY,
  first_name  VARCHAR(50)  NOT NULL,
  last_name   VARCHAR(50)  NOT NULL,
  email       VARCHAR(100) UNIQUE,
  city        VARCHAR(50),
  country     VARCHAR(50),
  join_date   DATE NOT NULL
);

CREATE TABLE employees (
  emp_id     INT AUTO_INCREMENT PRIMARY KEY,
  emp_name   VARCHAR(50) NOT NULL,
  job_title  VARCHAR(50),
  manager_id INT NULL,
  salary     DECIMAL(10,2),
  hire_date  DATE,
  FOREIGN KEY (manager_id) REFERENCES employees(emp_id)
);

CREATE TABLE orders (
  order_id    INT AUTO_INCREMENT PRIMARY KEY,
  customer_id INT NOT NULL,
  emp_id      INT,
  order_date  DATE NOT NULL,
  status      ENUM('Pending','Shipped','Delivered','Cancelled') DEFAULT 'Pending',
  FOREIGN KEY (customer_id) REFERENCES customers(customer_id),
  FOREIGN KEY (emp_id) REFERENCES employees(emp_id)
) AUTO_INCREMENT = 101;

CREATE TABLE order_items (
  item_id    INT AUTO_INCREMENT PRIMARY KEY,
  order_id   INT NOT NULL,
  product_id INT NOT NULL,
  quantity   INT NOT NULL CHECK (quantity > 0),
  unit_price DECIMAL(10,2) NOT NULL,
  FOREIGN KEY (order_id)   REFERENCES orders(order_id),
  FOREIGN KEY (product_id) REFERENCES products(product_id)
);

Databases

Create a table


The pattern is: table name, then each column with its type and rules.


USE shop_db;

CREATE TABLE suppliers (
  supplier_id  INT AUTO_INCREMENT PRIMARY KEY,
  supplier_name VARCHAR(100) NOT NULL,
  phone        VARCHAR(20),
  created_at   TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

DESCRIBE suppliers;    -- check the structure


Change a table with ALTER TABLE


ALTER TABLE suppliers ADD COLUMN email VARCHAR(100);           -- add a column
ALTER TABLE suppliers ADD COLUMN city VARCHAR(50) AFTER phone;  -- add in a position
ALTER TABLE suppliers MODIFY COLUMN phone VARCHAR(30);          -- change the type
ALTER TABLE suppliers RENAME COLUMN phone TO mobile;            -- rename a column
ALTER TABLE suppliers CHANGE COLUMN mobile phone VARCHAR(25);   -- rename + new type
ALTER TABLE suppliers DROP COLUMN city;                         -- remove a column
ALTER TABLE suppliers RENAME TO vendors;                        -- rename the table


Copy a table


CREATE TABLE products_backup LIKE products;          -- same structure, no rows
INSERT INTO products_backup SELECT * FROM products;  -- copy the rows

CREATE TABLE cheap_products AS                       -- structure + rows from a query
SELECT product_name, price FROM products WHERE price < 500;

Handling duplicates


-- skip the row silently if it breaks a UNIQUE or PRIMARY KEY rule
INSERT IGNORE INTO categories (category_name) VALUES ('Books');

-- if the key already exists, update instead (an "upsert")
INSERT INTO products (product_id, product_name, price, stock)
VALUES (2, 'Headphones', 2500.00, 60)
ON DUPLICATE KEY UPDATE stock = 60;

-- REPLACE deletes the old row and inserts the new one
REPLACE INTO categories (category_id, category_name) VALUES (4, 'Home & Kitchen');








UPDATE and DELETE


UPDATE changes existing rows. DELETE removes rows. Both need a WHERE clause, or they hit every row.


-- change one value
UPDATE customers SET city = 'Mumbai' WHERE customer_id = 2;

-- change several columns at once
UPDATE customers SET email = 'david@mail.com', city = 'Boston' WHERE customer_id = 7;

-- calculate from the old value: raise all Book prices by 10%
UPDATE products SET price = price * 1.10 WHERE category_id = 2;

-- UPDATE using a JOIN: cancel pending orders of customers from China
UPDATE orders o
JOIN customers c ON o.customer_id = c.customer_id
SET o.status = 'Cancelled'
WHERE c.country = 'China' AND o.status = 'Pending';


-- delete specific rows
DELETE FROM categories WHERE category_name = 'Sports';

-- delete the 2 oldest cancelled orders' items (ORDER BY + LIMIT)
DELETE FROM order_items WHERE order_id = 105 ORDER BY item_id LIMIT 2;


Always test with SELECT firstBefore you run UPDATE ... WHERE x or DELETE ... WHERE x, run SELECT * FROM table WHERE x. If the right rows appear, then change them. MySQL Workbench has “safe update mode” on by default, which blocks UPDATE or DELETE without a key in the WHERE clause (error 1175). Turn it off for a session with SET SQL_SAFE_UPDATES = 0;

Combining conditions


-- customers from India who joined after March 2024
SELECT first_name, city, join_date
FROM customers
WHERE country = 'India' AND join_date > '2024-03-31';
-- result: Priya, Chennai, 2024-05-10

-- use brackets when mixing AND with OR
SELECT product_name, price, category_id
FROM products
WHERE (category_id = 1 OR category_id = 3) AND price < 2000;
-- result: T-Shirt 599.00, Jeans 1499.00


Why brackets matterAND runs before OR. Without brackets, a OR b AND c means a OR (b AND c), which is often not what you wanted.


IN, BETWEEN and NOT


SELECT first_name, country FROM customers WHERE country IN ('UK', 'Spain', 'USA');
SELECT product_name, price FROM products WHERE price BETWEEN 300 AND 600;
SELECT order_id, order_date FROM orders WHERE order_date BETWEEN '2024-07-01' AND '2024-07-31';
SELECT order_id, status FROM orders WHERE status NOT IN ('Cancelled', 'Pending');


Text patterns with LIKE


% means “any number of characters (even none)”. _ means “exactly one character”.




PatternMatches


'A%'starts with A


'%a'ends with a


'%on%'contains “on”


'_i'two letters, second is i (like “Li”)




SELECT first_name FROM customers WHERE first_name LIKE 'P%';   -- Priya
SELECT city FROM customers WHERE city LIKE '%on%';             -- London
SELECT email FROM customers WHERE email LIKE '%@mail.com';

-- REGEXP for more powerful patterns: names starting with A, J or M
SELECT first_name FROM customers WHERE first_name REGEXP '^[AJM]';  -- Asha, John, Maria

SELECT first_name, last_name FROM customers WHERE email IS NULL;      -- David Brown

ORDER BY and LIMIT


ORDER BY sorts the result. LIMIT keeps only the first few rows.


SELECT product_name, price FROM products ORDER BY price;        -- lowest first (ASC is default)
SELECT product_name, price FROM products ORDER BY price DESC;   -- highest first

-- sort by country, then by first name inside each country
SELECT first_name, country FROM customers ORDER BY country ASC, first_name ASC;


Top N


SELECT product_name, price FROM products ORDER BY price DESC LIMIT 3;

Pages of results (pagination)


-- LIMIT count OFFSET skip
SELECT product_id, product_name FROM products ORDER BY product_id LIMIT 3 OFFSET 0;  -- page 1
SELECT product_id, product_name FROM products ORDER BY product_id LIMIT 3 OFFSET 3;  -- page 2
SELECT product_id, product_name FROM products ORDER BY product_id LIMIT 3, 3;        -- same as page 2


Second highest valueSELECT product_name, price FROM products ORDER BY price DESC LIMIT 1 OFFSET 1; returns Smartphone. This is a common interview question.

How to write any query


Most beginners get stuck on where to start, not on syntax. Use this method every time.


Question: “For each category, what is the total sales value of delivered orders, highest first?”


    

  1. What should the answer look like? One row per category, with two columns: category name, total sales.
    2. 

  2. Which tables hold that data? Category name is in categories. Sales come from order_items. “Delivered” is in orders. To get from items to categories you need products.
    3. 

  3. JOIN them along their keys: categories → products → order_items → orders.
    4. 

  4. Filter rows with WHERE: status = 'Delivered'.
    5. 

  5. Group and calculate: GROUP BY category, SUM the line totals.
    6. 

  6. Sort, limit, and check the result against a small manual calculation.
    7. 



SELECT c.category_name,
       SUM(oi.quantity * oi.unit_price) AS delivered_sales
FROM categories c
JOIN products    p  ON p.category_id = c.category_id
JOIN order_items oi ON oi.product_id = p.product_id
JOIN orders      o  ON o.order_id    = oi.order_id
WHERE o.status = 'Delivered'
GROUP BY c.category_name
ORDER BY delivered_sales DESC;

Views


A view is a saved SELECT that you can query like a table. It stores the query, not the data.


CREATE VIEW customer_sales AS
SELECT c.customer_id, c.first_name, c.country,
       COALESCE(SUM(oi.quantity * oi.unit_price), 0) AS total_spent
FROM customers c
LEFT JOIN orders o       ON o.customer_id = c.customer_id
LEFT JOIN order_items oi ON oi.order_id   = o.order_id
GROUP BY c.customer_id, c.first_name, c.country;

-- now use it like a table
SELECT * FROM customer_sales WHERE country = 'India' ORDER BY total_spent DESC;

CREATE OR REPLACE VIEW customer_sales AS ...;   -- change a view
SHOW FULL TABLES WHERE Table_type = 'VIEW';     -- list views
DROP VIEW customer_sales;


Why use views?Hide complex joins behind a simple name. Give users access to some columns without showing the whole table (for example, no salary column). Keep reports consistent because everyone uses the same logic.








Indexes and EXPLAIN


An index is like the index at the back of a book. Instead of reading every page (every row), MySQL jumps straight to the right place.


CREATE INDEX idx_customers_country ON customers(country);
CREATE UNIQUE INDEX idx_products_name ON products(product_name);
CREATE INDEX idx_orders_cust_date ON orders(customer_id, order_date);   -- composite index

SHOW INDEX FROM orders;
DROP INDEX idx_customers_country ON customers;


Check how MySQL runs a query


EXPLAIN SELECT * FROM orders WHERE customer_id = 1;


Look at the type column: ALL means it read every row (slow on big tables). ref, eq_ref or const mean it used an index. The key column shows which index. EXPLAIN ANALYZE (8.0.18+) also runs the query and reports real timings.


When to add an index




Good ideaBad idea


Columns often used in WHERE, JOIN ON, ORDER BYTiny tables

Things that stop an index being usedWrapping the column in a function: WHERE YEAR(order_date) = 2024. Write WHERE order_date >= '2024-01-01' AND order_date < '2025-01-01' instead. Transactions


A transaction groups several changes so they all succeed together or all fail together. Think of a bank transfer: money must leave one account and arrive in the other, never only one.




ACIDSimple meaning


AtomicityAll or nothing


ConsistencyRules (keys, constraints) are always kept


IsolationTransactions running at the same time do not mess each other up


DurabilityOnce saved (committed), changes survive a crash




-- place a new order and reduce stock: all or nothing
START TRANSACTION;

INSERT INTO orders (customer_id, emp_id, order_date, status)
VALUES (7, 3, CURDATE(), 'Pending');

SET @new_order = LAST_INSERT_ID();

INSERT INTO order_items (order_id, product_id, quantity, unit_price)
VALUES (@new_order, 6, 2, 599.00);

UPDATE products SET stock = stock - 2 WHERE product_id = 6;

COMMIT;        -- save everything
-- or ROLLBACK;  to undo everything since START TRANSACTION


Savepoints


START TRANSACTION;
UPDATE products SET price = price - 100 WHERE product_id = 7;
SAVEPOINT after_jeans;
UPDATE products SET price = 0 WHERE product_id = 6;      -- oops
ROLLBACK TO SAVEPOINT after_jeans;                       -- undo only the oops
COMMIT;


Good to knowMySQL runs in autocommit mode: each single statement is saved immediately unless you start a transaction. Transactions need the InnoDB storage engine, which is the default. DDL commands like CREATE or DROP cause an automatic commit and cannot be rolled back.

Loops


DELIMITER //
CREATE PROCEDURE count_to(IN p_max INT)
BEGIN
  DECLARE i INT DEFAULT 1;
  DECLARE result VARCHAR(255) DEFAULT '';
  WHILE i <= p_max DO
    SET result = CONCAT(result, i, ' ');
    SET i = i + 1;
  END WHILE;
  SELECT result;
END //
DELIMITER ;
CALL count_to(5);   -- 1 2 3 4 5

Triggers and events


A trigger runs automatically when a row is inserted, updated or deleted. An event runs automatically on a schedule.


Inside a trigger, NEW is the row after the change and OLD is the row before it.


-- reduce stock automatically when an item is sold
DELIMITER //
CREATE TRIGGER trg_reduce_stock
AFTER INSERT ON order_items
FOR EACH ROW
BEGIN
  UPDATE products SET stock = stock - NEW.quantity
  WHERE product_id = NEW.product_id;
END //

-- stop stock from going below zero
CREATE TRIGGER trg_check_stock
BEFORE UPDATE ON products
FOR EACH ROW
BEGIN
  IF NEW.stock < 0 THEN
    SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = 'Not enough stock';
  END IF;
END //
DELIMITER ;

JSON in MySQL


The JSON type stores flexible data, like product specifications that differ for each product.

SELECT JSON_ARRAYAGG(JSON_OBJECT('id', category_id, 'name', category_name)) FROM categories;

Normalization: design good tables


Normalization means splitting data so each fact is stored in one place. This avoids repeated data and mistakes.


A bad design puts everything in one table:


order_idcustomer_namecustomer_cityproducts


101Asha KumarChennaiLaptop, Headphones


103Asha KumarChenaiSmartphone


Problems: the city is repeated (and misspelled once), and many products sit in one cell.




FormRule in simple wordsFix in our example


1NFOne value per cell. No repeating lists.Move each product to its own row in order_items


2NFEvery column depends on the whole primary key, not part of it.Product name depends only on product_id, so it lives in products


3NFColumns depend only on the key, not on other non-key columns.Customer city depends on the customer, so it lives in customers




That is exactly how shop_db is designed. Notice one deliberate exception: order_items.unit_price copies the price at the time of sale, because product prices change later. Copying data on purpose for a clear reason is called denormalization.

Show answer
SELECT first_name, join_date FROM customers

Easy
4. Show the 3 products with the highest stock value (price × stock).


Show answer
SELECT product_name, price * stock AS stock_value
FROM products ORDER BY stock_value DESC LIMIT 3;

Medium
5. Count products in each category, showing the category name.


Show answer
SELECT c.category_name, COUNT(p.product_id) AS products
FROM categories c
LEFT JOIN products p ON p.category_id = c.category_id
GROUP BY c.category_name;
-- Electronics 3, Books 2, Clothing 2, Home 1



Medium
6. Show how much every customer has spent, including customers who spent nothing (show 0).


Show answer
SELECT c.first_name,
       COALESCE(SUM(oi.quantity * oi.unit_price), 0) AS total_spent
FROM customers c
LEFT JOIN orders o       ON o.customer_id = c.customer_id
LEFT JOIN order_items oi ON oi.order_id   = o.order_id
GROUP BY c.customer_id, c.first_name
ORDER BY total_spent DESC;
-- Asha 90000, Priya 56000, Ravi 4848, John 3895, Maria 2500, Li 1050, David 0



Medium
7. Which product sold the most units?


Show answer
SELECT p.product_name, SUM(oi.quantity) AS units_sold
FROM order_items oi
JOIN products p ON p.product_id = oi.product_id
GROUP BY p.product_name
ORDER BY units_sold DESC
LIMIT 1;
-- Coffee Mug, 6



Medium
8. For each manager, show how many people report directly to them.


Show answer
SELECT m.emp_name AS manager, COUNT(e.emp_id) AS direct_reports
FROM employees e
JOIN employees m ON e.manager_id = m.emp_id
GROUP BY m.emp_name;
-- Meena 2, Arjun 2, Kavya 1



Medium
9. Show total sales for each month of 2024.


Show answer
SELECT DATE_FORMAT(o.order_date, '%Y-%m') AS month,
       SUM(oi.quantity * oi.unit_price) AS sales
FROM orders o
JOIN order_items oi ON oi.order_id = o.order_id
WHERE YEAR(o.order_date) = 2024
GROUP BY month
ORDER BY month;
-- 2024-06 61850, 2024-07 33895, 2024-08 3550, 2024-09 58998



Medium
10. List products that have never been ordered. Write it two ways.


Show answer
-- with LEFT JOIN
SELECT p.product_name FROM products p
LEFT JOIN order_items oi ON oi.product_id = p.product_id
WHERE oi.item_id IS NULL;

-- with NOT EXISTS
SELECT product_name FROM products p
WHERE NOT EXISTS (SELECT 1 FROM order_items oi WHERE oi.product_id = p.product_id);
-- Gift Card



Hard
11. Find the second most expensive product without using LIMIT.


Show answer
SELECT product_name, price FROM products
WHERE price = (SELECT MAX(price) FROM products
               WHERE price < (SELECT MAX(price) FROM products));

Hard
12. Rank customers by total spending using DENSE_RANK.


Show answer
WITH spend AS (
  SELECT o.customer_id, SUM(oi.quantity * oi.unit_price) AS total
  FROM orders o JOIN order_items oi ON oi.order_id = o.order_id
  GROUP BY o.customer_id
)
SELECT c.first_name, s.total,
       DENSE_RANK() OVER (ORDER BY s.total DESC) AS spend_rank
FROM spend s JOIN customers c ON c.customer_id = s.customer_id;



Hard
13. Show each category’s share of total revenue as a percentage.


Show answer
SELECT c.category_name,
       SUM(oi.quantity * oi.unit_price) AS revenue,
       ROUND(100 * SUM(oi.quantity * oi.unit_price)
             / SUM(SUM(oi.quantity * oi.unit_price)) OVER (), 2) AS pct
FROM order_items oi
JOIN products p   ON p.product_id  = oi.product_id
JOIN categories c ON c.category_id = p.category_id
GROUP BY c.category_name
ORDER BY revenue DESC;
-- Electronics 147500 (93.18), Clothing 6893 (4.35), Books 2400 (1.52), Home 1500 (0.95)



Hard
14. Create a view delivered_orders showing order id, customer name and order total for delivered orders only.


Show answer
CREATE VIEW delivered_orders AS
SELECT o.order_id, c.first_name, SUM(oi.quantity * oi.unit_price) AS total
FROM orders o
JOIN customers c    ON c.customer_id = o.customer_id
JOIN order_items oi ON oi.order_id   = o.order_id
WHERE o.status = 'Delivered'
GROUP BY o.order_id, c.first_name;

SELECT * FROM delivered_orders;
-- 101 Asha 60000, 102 Ravi 1850, 104 John 3895, 107 Priya 56000



Hard
15. Write a stored procedure products_under(max_price) that lists products cheaper than the given price.


Show answer
DELIMITER //
CREATE PROCEDURE products_under(IN p_max DECIMAL(10,2))
BEGIN
  SELECT product_name, price FROM products
  WHERE price < p_max ORDER BY price;
END //
DELIMITER ;

CALL products_under(500);
-- Coffee Mug 250.00, Novel: The Sky 300.00, SQL Basics Book 450.00








Cheat sheet


The full shape of the most used statements. Square brackets mean optional.




SELECT
SELECT [DISTINCT] cols
FROM t
[JOIN t2 ON ...]
[WHERE cond]
[GROUP BY cols]
[HAVING cond]
[ORDER BY cols [DESC]]
[LIMIT n [OFFSET m]];

UPDATE t SET a = 1 WHERE id = 5;
DELETE FROM t WHERE id = 5;

ALTER TABLE t ADD COLUMN c INT;
ALTER TABLE t DROP COLUMN c;
